## Session du 14 juin — Bugs corrigés

### Bug 1 : L'hôte pouvait répondre pour une équipe ✅

**Cause racine** : `Lobby.tsx` naviguait vers `/game/:code` (page `Game.tsx` qui contient un `QuestionCard` interactif et `isCurrentTeam={true}`) au lieu de `/game/:code/host` (`HostGame.tsx`).

**Corrections :**
- `Lobby.tsx` → `navigate(`/game/${code}/host`)`
- `Game.tsx` → `isCurrentTeam={false}` pour ping-pong (sécurité)
- `HostGame.tsx` : nombreux fixes (voir ci-dessous)

### Bug 2 : Réponse correcte côté hôte ≠ côté équipes ✅

**Cause** : `handleAllAnswered` (WaitingForTeams auto-advance) :
1. Validait Q40
2. **Immédiatement** lançait `forceNewQuestion()` → Q41 défini dans le backend
3. L'hôte voyait encore le résultat Q40 mais le backend était sur Q41
4. Si l'hôte cliquait "Valider les réponses" → validait Q41 (sans rapport)

**Corrections dans `HostGame.tsx` :**
- `handleAllAnswered` valide la question courante **sans** auto-avancer
- Bouton "Valider les réponses" est `disabled` quand `answerResult` est déjà affiché
- `forceNewQuestion` efface `answerResult` (réactive le bouton pour la nouvelle question)

**Corrections backend (`main.py`) :**
- `submit_answer` : garde contre les réponses en double (même équipe, même question)
- `validate_answers` : set `teams_processed` pour dédupliquer par équipe
- `get_answers_status` : `answered_ids = list(set(...))` pour éviter doubles
- `get_team_specific_state` : même déduplication

## 🐛 Bug connu (à corriger prochaine session)

### Points toujours affichés à 0 après une bonne réponse

**Symptôme** : Dans `TeamScreen`, après avoir répondu correctement, l'interface affiche **0 point** au lieu des points réels.

**Cause** : Le backend retourne intentionnellement `points_earned: 0` lors du `submit_answer` :
```python
# backend/main.py, endpoint POST /answers/
return {
    "is_correct": is_correct,
    "correct_answer": question.correct_answer,
    "points_earned": 0,   # ← toujours 0 ici
    "team_score": team.score,
    "pending_validation": True
}
```
Les vrais points sont distribués par `validate_answers` (POST `/games/{code}/validate-answers`).

**Mais** : `TeamScreen` affiche le résultat du `submitAnswer` (qui a `points_earned = 0`) et **ne re-poll pas les scores après la validation de l'hôte**.

**Fixes possibles** :
1. **Option simple** : dans `TeamScreen`, après que `answerResult` est affiché, continuer à poller `get_team_specific_state` et mettre à jour `team_score`. Afficher le score du team (qui augmentera après validation hôte) plutôt que `points_earned` du submitAnswer.
2. **Option directe** : modifier `submit_answer` pour calculer et retourner directement les vrai points (et supprimer la validation séparée). Risque : change l'architecture de validation manuelle par l'hôte.
3. **Option propre** : ajouter un endpoint `GET /answers/{questionId}/team/{teamId}/result` que TeamScreen poll après soumission, pour obtenir le résultat post-validation (avec le vrai `points_earned`).

**Endroits clés à modifier :**
- `frontend/src/pages/TeamScreen.tsx` : affichage du résultat (chercher `answerResult.points_earned`)
- `backend/main.py` : `submit_answer` et/ou `validate_answers`

## Architecture actuelle

```
Lobby.tsx
  ├─ navigate('/game/:code/host')   → HostGame.tsx  (hôte)
  └─ navigate('/game/:code/team/:id') → TeamScreen.tsx (équipes)

HostGame.tsx flow :
  forceNewQuestion() → setCurrentQuestionApi() → setWaitingForTeams(true) + startPolling()
  WaitingForTeams détecte all_answered → handleAllAnswered() → handleValidateAnswers()
  Hôte voit résultat → clique "Tour suivant" → forceNewQuestion() (efface answerResult)

TeamScreen.tsx flow :
  getTeamState() poll toutes les 2s → voit current_question
  Équipe répond → submitAnswer() → affiche answerResult (points = 0 ← BUG)
  Quand question change (useEffect) → efface answerResult → affiche nouvelle question
```
